# Code guidelines

Conventions for codecs in this repo. The closest existing codec wins over any rule below — mimic it first.

## Codec layout

Each format lives in `lib/src/<name>/` (folder and model file share the snake_case short name, e.g. `gimp/gimp.dart`, `paint_dot_net/paint_dot_net.dart`):

- `<name>.dart` — models only.
- `decode.dart` / `encode.dart` — `part of '<name>.dart';` with private `_decode(bytes)` / `_encode(palette)`.
- `<name>.mapper.dart` — generated by `scripts/generate-code.bash`, never hand-edited.

## Model file (`<name>.dart`)

- Imports by kind: binary → `package:buffer/buffer.dart`; text → `dart:convert` + `src/text_parse_utils.dart`; XML → `package:xml/xml.dart` + `src/xml_decode_utils.dart` / `src/xml_encode_utils.dart`. Always `package:dart_mappable/dart_mappable.dart`.
- Header block comment with labeled fields in fixed order (omit a line when unknown): `Format name:`, `Acronym:` (omit when none), `Versions:` (from code constants), `File extensions:` (always plural, must match `docs/supported-formats.md`), `Applications:`, optional `Format details:` (wire-layout or provenance notes), and `References:` links, one per `- ` line (see `acf.dart`, `psp.dart`). Wrap prose values exceeding 80 columns onto ` *   ` continuation lines; keep URLs on their own lines even when long. Mirror new links in `docs/references.md`.
- Classes: `<Name>Palette` + `<Name>PaletteColor`, both `@MappableClass()` with `XxxMappable` mixins.
- Keep `@MappableEnum()`s clean (no methods or statics). Convert wire values with file-level functions using `return switch` expressions (see `lib/src/acf/decode.dart`, `lib/src/acf/encode.dart`).
- Document fields: `/// Value: [0..255]`, units, optionality, raw-vs-decoded semantics (e.g. ACF stores raw 16-bit RGB).
- Assert ranges and shapes with messages (`'red must be between 0 and 255'`), but never rely on asserts for format errors (they vanish in release builds).
- Palette class exposes wire constants (`validFileSignature`, `validVersion`, separators) as `static const` and uses them in decode, encode, and tests.
- Standard API: `factory fromBytes`, `toBytes()`, `static isValidFormat` (try `_decode`, catch-all → `false`). Only deviate with a documented reason (e.g. Procreate v1 has no `fromBytes` — multi-palette archive decoded via a top-level function).

## Decode

- Signature: `XxxPalette _decode(List<int> bytes)`.
- Text: `splitLines(bytes)`, positional `lines.elementAt(i)`, `validateHeader` / `validateVersion` from `text_parse_utils`; strict `int.parse` for fixed layouts (`psp`, `acf`), tolerant regex + `parseIntValue` / `parseStringValue` for loose ones (`gimp`, `koffice`).
- Binary: `ByteDataReader()..add(bytes)`, a `_validateVersion(buffer)` helper, per-variant `_readXxx` helpers, `switch` expressions on the color-space enum (see `aco/decode.dart`).
- XML: `utf8.decode` → `parseXml` → `validateRootElement` → `parseElements` / `parseIntAttribute`; tag/attribute names go in a constants class (see `AcblConstants` in `acbl/`).
- Fail fast with `FormatException` naming the palette. Derive counts from the data you actually parsed.

## Encode

- Signature: `List<int> _encode(XxxPalette palette)`.
- Binary: `ByteDataWriter` with a `// comment` per section and `_writeXxx` helpers behind a `switch` on the enum (see `aco/encode.dart`).
- Text: `List<String>` + `join('\n')` (no trailing newline).
- Counts (`Entries:`, `Inks:`) are derived from `palette.colors.length` / `palette.inks.length`, never stored.
- Must round-trip: `fromBytes(toBytes(p))` deep-equals `p`, and sample files re-encode byte-for-byte (covered by tests).

## Checks

- `scripts/generate-code.bash` after touching models (`build_runner` + `dart format`).
- `flutter analyze` must report no issues (`very_good_analysis`, 80 columns, prefer-const, type annotations).
- `flutter test` — full suite green.

## Tests & docs

- Samples: 1+ real files in `test/testdata/<name>/`, covering each format version/branch. The 1j01/palettes repo (see `docs/references.md`) is a candidate source for sample files.
- Test file `test/<name>_test.dart` (see `test/gimp_test.dart`): expected first color per sample, `isValidFormat` true/false, write → read round-trip (temp file deleted after), byte-for-byte re-encode of samples. Assert literal expectations — don't re-parse fixtures to build them.
- Wire-up: export in `lib/color_palette_formats.dart` (alphabetical), usage blocks in `example/example.dart` + `example/decoding.dart`, row in `docs/supported-formats.md`, bullet in `README.md`.
